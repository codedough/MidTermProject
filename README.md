# Fresh Produce Shortage Early Warning

Can we predict, one to three months ahead, whether a grocery store will run short of a fresh fruit or vegetable, using weather, past availability and prices? This project trains a model to answer that and serves it as a web service (FastAPI, Docker).

## 1. The problem

Fresh produce availability swings with the seasons, the weather, fuel costs and supply disruptions. Weather affects supply with a delay of a month or two, so it should give some advance notice of trouble.

- **What is predicted.** At the end of month *t*, whether a given product at a given store will have a **shortage** in month *t+h*, for *h* = 1, 2 or 3 months. A shortage means availability below 82% of the month (`shortage_flag = 1`). This is binary classification, trained separately for each horizon.
- **Who benefits.** A store buyer or category manager who knows a shortage is likely next month can reorder early, switch suppliers, raise prices gradually or warn customers. The same idea works for a wholesaler or a food bank planning supply.
- **How the model is used.** Each month, for each store-product, send the latest availability, prices and weather to `POST /predict`. The service returns a shortage probability and a yes/no warning. Buyers act on the warnings and review the highest probabilities first.
- **Evaluation metric.** About 9% of rows are shortages, so the classes are imbalanced and accuracy is misleading: always answering "no shortage" is 91% accurate and useless. The main metric is **PR-AUC** (area under the precision-recall curve; a model with no skill scores about 0.08, a perfect one 1.0). We also report ROC-AUC, and precision, recall and F1 at the alert threshold. **Why it matters:** a missed shortage means empty shelves and lost sales (recall), and a false alarm means over-ordering and waste (precision). PR-AUC measures how well the model balances the two on the rare class, and the threshold lets a business trade one for the other.

**Questions the project answers**

1. How much warning can a model give, and how fast does it fall off with the horizon?
2. Do weather features help beyond what last month's availability already tells you?
3. Which features matter most?

**The data is simulated.** It is generated by `generate_produce_data.py` from explicit rules (seasonality, weather, inflation, fuel cost, store effects, supply shocks), not collected from stores. The project validates a method; it does not describe the real produce market. For real data, see USDA ERS Fruit and Vegetable Prices, BLS average retail food prices and NOAA climate data.

## 3. Data: source and retrieval

The dataset is committed at `data/synthetic_produce_prices_1990_2025.csv`, so nothing needs downloading. To recreate it exactly (the same seed gives the same file; the notebook checks this):

```bash
python generate_produce_data.py --seed 42 --rows 10000
```

One row is one product at one store in one month (Jan 1990 to Dec 2025): 12 products, 4 stores (one per US region), 24 store-product series. About 3.5% of months have no report. The column reference is at the end of this file.

## 4. How to run

You need Python 3.13 (the version everything was tested with). Choose **uv** (recommended, uses the exact locked versions) or **pip**.

**With uv** ([install](https://docs.astral.sh/uv/getting-started/installation/)):

```bash
uv sync --locked                 # add --extra notebook for Jupyter and plots
uv run python train.py
uv run python serve.py
```

**With pip:**

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python train.py
python serve.py
```

### 4.1 Explore and tune: the notebook

```bash
uv sync --locked --extra notebook
uv run jupyter lab notebook.ipynb
```

(With pip: `pip install -r requirements.txt matplotlib jupyterlab`.) The notebook is already executed, so you can read it as is. Running it from scratch takes about 5 minutes, mostly the tuning section. It writes `model_config.json`.

### 4.2 Train

```bash
python train.py
```

This reads `model_config.json`, trains one model per horizon (1, 2 and 3 months), picks a decision threshold on the validation years, prints test-year metrics and saves everything to `model/shortage_model.bin` (about 5 seconds). Use `--refit-all` to also learn from the test years before saving.

### 4.3 Predict from the command line

```bash
python predict.py sample_request.json
python predict.py '{"store_id":"S04","product":"strawberries","horizon":2,"month":9,"avail":84.5}'
```

### 4.4 Run the web service

```bash
python serve.py                  # http://localhost:9696, interactive docs at /docs
python predict_test.py           # in another terminal: sends sample requests
```

### 4.5 Run it in Docker

```bash
docker build -t myproject .
docker run -it -p 9696:9696 myproject
```

Then call it as in section 5. The image installs the pinned `requirements.txt` on `python:3.13-slim`, copies the code and the saved model, runs as a non-root user, and starts `python serve.py` on port 9696 with a health check.

> **Note:** Docker was not available in the environment where this project was built, so the image itself has not been built. I tested the same steps by copying exactly the files the Dockerfile copies into an empty folder, installing `requirements.txt` in a fresh Python 3.13 environment, and running `python serve.py`. If `docker build` fails on your machine, please check that the `python:3.13-slim` base image can be pulled.

The model is a pickle file, so it is only guaranteed to load with the library versions that saved it (`requirements.txt` pins them). If you retrain with different versions, update the pins.

## 5. Using the service

### `GET /health`

Returns HTTP 200 and the status:

```bash
curl http://localhost:9696/health
# {"status":"ok","horizons":[1,2,3],"model":"xgboost","trained_at":"..."}
```

### `POST /predict`

Send a JSON object describing what you know at the end of month *t*. The service returns the probability of a shortage `horizon` months later.

```bash
curl -X POST -H "Content-Type: application/json" -d '{"store_id": "S04", "product": "strawberries", "horizon": 2, "month": 9, "avail": 84.5}' http://localhost:9696/predict
```

Response:

```json
{"store_id":"S04","product":"strawberries","horizon":2,"month_predicted":11,"shortage_probability":0.0641,"shortage_warning":false,"threshold":0.3332,"missing_features":["avail_lag1","..."]}
```

That request supplies only the five required fields. A request with everything the model uses is in `sample_request.json` (a real case from the test years: tomatoes at the South store in February 2022, during a dry spell; a shortage did follow in March):

```bash
curl -X POST -H "Content-Type: application/json" -d @sample_request.json http://localhost:9696/predict
```

```json
{"store_id":"S03","product":"tomatoes","horizon":1,"month_predicted":3,"shortage_probability":0.8557,"shortage_warning":true,"threshold":0.3313,"missing_features":[]}
```

`shortage_warning` is true when the probability is at or above the horizon's `threshold`, chosen to maximise F1 on validation data. Invalid input (unknown field, unknown store or product, a store that does not carry the product, out-of-range value, bad JSON) returns HTTP 422 with an explanation.

**Required fields**

| Field | Meaning |
|---|---|
| `store_id` | `S01` Northeast, `S02` Midwest, `S03` South, `S04` West |
| `product` | tomatoes, lettuce, strawberries, apples, bananas, oranges, potatoes, carrots, broccoli, avocados, grapes, onions. Each store carries only 6 (see the table in the dataset reference); other combinations are rejected. |
| `horizon` | 1, 2 or 3 months ahead |
| `month` | The current month *t*, 1-12. The service predicts month `month + horizon`. |
| `avail` | Availability this month, 0-100 (%) |

**Optional fields.** Anything you leave out is treated as unknown (listed in `missing_features`). Predictions are better when you supply them, because the model was trained with all of them.

| Field | Meaning |
|---|---|
| `avail_lag1`, `avail_lag2`, `avail_lag3`, `avail_lag12` | Availability 1, 2, 3 and 12 months ago |
| `real_logprice`, `real_logprice_lag1`, `real_logprice_lag12` | Inflation-adjusted log price now, 1 and 12 months ago. Compute as `ln(price) - 0.85 * ln(cpi_index / 100)`, with `cpi_index` as in the dataset (Jan 1990 = 100). |
| `fuel_cost_index` | Fuel cost index (1990 = 100) |
| `drought_index`, `drought_index_3m` | Regional drought index now and its 3-month average (negative = dry) |
| `frost_days`, `frost_days_3m` | Frost days this month and the 3-month average |
| `heatwave_days`, `heatwave_days_3m` | Heat-stress days this month and the 3-month average |
| `temp_anomaly_c`, `temp_anomaly_c_3m` | Temperature anomaly now and its 3-month average |
| `enso_index`, `enso_index_3m` | ENSO-like climate index now and its 3-month average |

## 6. Method and results

Everything is in `notebook.ipynb`; `train.py` repeats the final step.

- **Features and split.** Features are built for each store-product on a complete monthly calendar, so lags are by date even where a month is missing. Every feature is known at month *t* (the notebook checks that rebuilding the features from data that stops at *t* gives identical values). Data is split by the month being predicted: train 1991-2015, validation 2016-2020, test 2021-2025.
- **EDA.** Missing months (3.5%, in random gaps) are left blank rather than filled; outliers in weather and price are real extremes and are kept; availability is the strongest correlate of shortage; dry and hot conditions cut availability with a delay, by different amounts for each product.
- **Models.** A logistic-regression baseline, a decision tree, a random forest and XGBoost, all as `DictVectorizer` pipelines, against three rule-based baselines. Hyperparameters were tuned by random search with **time-ordered cross-validation** (three folds: train up to 2005, 2010 and 2015, score on the next five years). Shuffled K-fold would use future months to predict earlier ones and flatters the score (0.70 against 0.65 here).

**Cross-validation summary** (PR-AUC, mean over three time-ordered folds):

| Model | Default | Tuned | 1 month | 2 months | 3 months |
|---|---|---|---|---|---|
| XGBoost | 0.499 | **0.500** | 0.647 | 0.455 | 0.397 |
| Random forest | 0.494 | 0.496 | 0.633 | 0.453 | 0.403 |
| Logistic regression (baseline model) | 0.482 | 0.482 | 0.665 | 0.442 | 0.340 |
| Decision tree | 0.341 | 0.379 | 0.544 | 0.313 | 0.280 |
| Rule: same as now (persistence) | | 0.201 | 0.331 | 0.163 | 0.108 |
| Rule: same month last year | | 0.197 | 0.197 | 0.197 | 0.197 |

The top three are within the fold-to-fold spread (about 0.08), so they are effectively tied. XGBoost has the highest mean and was selected. Logistic regression is just as good at 1 month ahead and falls behind at 3 months.

- **Feature importance.** At 1 month ahead, current availability dominates (shuffling it cuts validation PR-AUC by 0.45; the next group, price, by 0.07). At 3 months ahead it barely matters (0.04); inflation-adjusted price, store and product, weather and the calendar month take over, and weather's share grows with the horizon (0.06 to 0.09).
- **Final test results (2021-2025)**, model refit on 1991-2020, threshold chosen on validation:

| | 1 month | 2 months | 3 months |
|---|---|---|---|
| PR-AUC | **0.61** | **0.45** | **0.43** |
| ROC-AUC | 0.93 | 0.88 | 0.87 |
| Precision at threshold | 0.49 | 0.49 | 0.48 |
| Recall at threshold | 0.59 | 0.43 | 0.37 |
| F1 at threshold | 0.54 | 0.46 | 0.42 |
| Same as now (persistence), PR-AUC | 0.31 | 0.22 | 0.12 |
| No skill, PR-AUC | 0.08 | 0.08 | 0.08 |

At 1 month ahead the model catches about 60% of shortages, and about half of its warnings are real shortages.

**Limitations.** The data is simulated. The test years contain only 116 shortages and include an unusual stretch (the 2020-2021 spike, then calm years), so results could differ on another period; small changes such as the order of the training rows moved test PR-AUC by about 0.02 in my runs, so treat differences of that size as noise. Probabilities are not calibrated (the model was trained with `scale_pos_weight=3`): use them to rank risk and use the threshold for warnings. Results vary a lot by product, and for products with very few shortages (potatoes, bananas, carrots, onions) the model has little to learn from. Weather adds only modest accuracy in this data, and regional weather stands in for supply conditions at the store, not for where the produce is grown.

# Dataset reference

- **Rows:** 10,000, **columns:** 25, no missing cells
- **Grain:** one row = one product at one store in one month
- **Gaps:** the full panel is 10,368 rows; 368 (3.5%) are dropped at random to mimic missing price reports
- **Series:** each store carries 6 of the 12 products and each product is sold by exactly 2 stores

| Store | Region | Tier | Carries |
|---|---|---|---|
| S01 FreshMart Northeast | Northeast | premium | tomatoes, lettuce, strawberries, apples, bananas, avocados |
| S02 ValueGrocer Midwest | Midwest | discount | potatoes, carrots, onions, apples, bananas, oranges |
| S03 SunCoast Market | South | mainstream | oranges, tomatoes, lettuce, broccoli, grapes, onions |
| S04 PacificFresh | West | premium | strawberries, broccoli, avocados, grapes, potatoes, carrots |

| Column | Meaning |
|---|---|
| `record_id`, `date`, `year`, `month` | Row id and month start date |
| `store_id`, `store_name`, `region`, `store_tier` | Store, its US region and price tier |
| `product`, `unit` | One of the 12 products; unit is lb |
| `price_usd_per_lb` | Retail price in nominal USD per pound |
| `availability_pct` | Share of the month the item was in stock, 0-100 |
| `shortage_flag` | 1 if `availability_pct` < 82 (the target in this project) |
| `avg_temp_c`, `temp_anomaly_c` | Regional monthly mean temperature and its departure from the 1990 baseline (includes a warming trend) |
| `precip_mm` | Regional monthly precipitation |
| `drought_index` | Palmer-style index. **Negative = dry, positive = wet** |
| `frost_days`, `heatwave_days` | Count of frost days and heat-stress days in the month |
| `enso_index` | National ENSO-like climate index |
| `cpi_index` | Consumer price index, Jan 1990 = 100 (approximate US inflation) |
| `fuel_cost_index` | Stylised fuel/freight cost index, 1990 = 100 (simulated) |
| `import_disruption_index` | Shipping/import disruption (standardised; higher = worse) |
| `promotion_flag` | 1 if the item was on promotion that month |
| `covid_period` | 1 for Mar 2020 to Dec 2021 |

**Built-in cause and effect.** Prices follow CPI (85% pass-through) plus a small per-product drift, and are highest off-season. Heat, drought, excess rain and frost raise prices and cut availability, with a lag (50% same month, 30% one month earlier, 20% two months earlier), and sensitivity differs by product (avocados and tomatoes react to drought, lettuce and broccoli to heat, bananas and onions barely react). Premium stores cost more, discount stores less. Fuel cost, import disruptions (strongest for bananas and avocados), promotions (about 10% lower price) and the covid period also matter.
